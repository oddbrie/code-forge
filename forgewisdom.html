Web Basics 🌐

What happens when you visit a website

Meaning:

By typing a url into your browser, you are requesting a server to return a series of files [like HTML, CSS, and JavaScript files], and the browser then reads those files and displays the website on your screen.

Why it matters:

This process involves a lot of communication between the browser and the server, and understanding this process is crucial for web development.

Real-world example:

When I visit Reddit, my browser sends a request to Reddit’s servers, which then return the HTML, CSS, and JavaScript files that make up the Reddit website. My browser then reads those files and displays the Reddit website on my screen; I am able to see the posts, comments, and interact with the site because of this process.

My Note:

I am not sure, other than my brief experience with MySpace in the early 2000s, if I ever really thought about how websites work before. I understood that there were servers and browsers, but I never really thought about the communication process between them. And I definitely never thought about how the browser reads the files and displays the website on the screen. It’s interesting to break it down and see how it all works together.

Browser vs Server

Meaning:

A browser is a software application that allows users to view websites [like Chrome or Safari], while a server stores everything. The browser asks the server to return a website, and the server sends back the data needed to display the requested website on the user's screen.

Why it matters:

It's important to know that my computer does not "hold" the website; instead it is stored on a server somewhere else. When I visit a website, my browser is essentially asking the server to send the website data to my computer. Communication. This explains why websites can be slow, unavailable, or behave differently depending on the server.

Real-world example:

When I open a website like Reddit, my browser (I use Chrome) sends a request to Reddit's servers. Reddit's servers then process that request and send back the necessary files [HTML, CSS, JavaScript] and my browser displays it so I can read posts, view comments, and interact with the site.

My Note:

I used to think that the browser and the website were basically the same thing. I now understand that the browser is the viewing software and the server is where the website data actually lives. This is a fundamental concept that I had not fully grasped before, and it helps me understand how the web works on a deeper level.

Request vs Response

Meaning:

A request is when a browser asks a server for something, like a website or data. A response is when the server sends back data or files to the browser. This back and forth communication is how the web works, from first request [loading] to each additional request [updating].

Why it matters:

The fundamental process of the web is based on this request-response cycle. And understanding this highlights how every action on a website works. Whether it's loading a page, submitting a form, or clicking a button, it all involves requests and responses between the browser and the server. This is the core of how the web functions.

Real-world example:

When I go to Reddit, my browser sends a request to Reddit's servers asking for the homepage. The server responds by sending back the necessary files and data, and my browser then builds and displays the Reddit homepage on my screen. If I click on a post, that action sends another request to the server and another response is returned.

My Note:

It's strange to stop and think about how often this happens, it's not just when I load a page... every click or action can trigger another request and response. This creates the dynamic loop of interaction on the web, and it's fascinating to understand how it all works together.

HTML Knowledge 🧾

What HTML is for

Meaning:

HTML is used to create the structure and content of a webpage. It tells the browser what each part of the page is, such as headings, paragraphs, links, images, lists, and sections. It is the foundation of a webpage and gives everything a place and purpose.

Why it matters:

HTML matters because every webpage needs structure before it can be styled or made interactive. Without HTML, there would be nothing for CSS to style or for JavaScript to work with. It also helps organize content in a way that browsers, developers, and assistive technologies can understand.

Real-world example:

On a website like Reddit, HTML is what defines the layout of the content on the page. It separates things like post titles, usernames, comment sections, buttons, and navigation areas into meaningful parts so the browser knows what to display and how the page is organized.

My Note:

I used to think HTML was just about putting words and images onto a screen, but I now understand that it is really about structure and meaning. It creates the base of the page and gives everything a role before any styling or functionality is added.

Semantic Structure

Meaning:

Semantic structure means using HTML elements that describe what the content actually is, instead of just using generic elements for everything. It gives the page clearer meaning by labeling parts of it as things like headings, navigation, sections, articles, or footers.

Why it matters:

Semantic structure matters because it makes a webpage easier to read, understand, and maintain. It also helps with accessibility and allows browsers, search engines, and assistive technologies to better understand the content and purpose of each part of the page.

Real-world example:

On a blog page, semantic structure would mean separating the navigation menu from the main article content and from the footer at the bottom of the page. This makes the page more organized and gives each area a clear purpose instead of everything being treated like the same type of content.

My Note:

This makes me realize that HTML is not just about placing content on a page, but about defining what that content actually is. Semantic structure seems important because it helps make a page more organized and meaningful, not just visible.

CSS Styling 🎨

What CSS is for

Meaning:

CSS is used to control how a webpage looks and is visually presented. It is responsible for things like colors, spacing, layout, fonts, and positioning of elements on the page. While HTML creates the structure, CSS defines the appearance of that structure.

Why it matters:

CSS matters because without it, a webpage would just look like plain text with no organization or design. It allows developers to make websites readable, visually appealing, and easier to navigate. It also helps create consistent styling across an entire site.

Real-world example:

On a website like Reddit, CSS controls how posts are spaced, how text is styled, how buttons look, and how the layout is arranged. It is what makes the site look clean and organized instead of just a block of raw content.

My Note:

I used to think HTML controlled how things looked, but I now understand that HTML only defines what things are, and CSS is what makes them look the way they do. It separates structure from appearance, which makes everything more organized and easier to manage.

Layout and Spacing

Meaning:

Layout and spacing refer to how elements are arranged on a page and how much space exists between them. This includes how content is positioned, aligned, and distributed across the screen to create a clean and readable design.

Why it matters:

Proper layout and spacing make a webpage easier to read and understand. Without spacing and structure, content can feel cluttered and confusing. Good layout helps guide the user's attention and makes the page feel organized and intentional.

Real-world example:

On a site like YouTube or Reddit, spacing separates posts, comments, and sections so they are easy to distinguish. Layout determines where navigation appears, where content is placed, and how everything fits together on the screen.

My Note:

This makes me realize that design is not just about colors or fonts, but about how things are arranged. Spacing seems like a small detail, but it actually has a big impact on how easy a page is to use and understand.

JavaScript Concepts ⚡

What JavaScript does

Meaning:

JavaScript is used to make a webpage interactive and dynamic. It allows a website to respond to user actions, change content, and update parts of the page without needing to reload everything. It works with the HTML structure and can modify it while the page is running.

Why it matters:

JavaScript matters because it turns a static webpage into something interactive. Without it, a site would only display information, but with it, users can click buttons, submit forms, see updates, and interact with the page in real time.

Real-world example:

On a site like Reddit, JavaScript allows things like expanding comments, voting on posts, and loading new content without refreshing the entire page. It updates parts of the page based on user actions.

My Note:

I used to think websites were mostly just built and displayed, but now I understand that JavaScript is what allows them to change and react. It makes the page feel alive instead of just being a static display.

Events and Interaction

Meaning:

Events are actions that happen on a webpage, usually triggered by the user, such as clicking, typing, or scrolling. JavaScript can listen for these events and run specific code in response to them, allowing the page to react to what the user is doing.

Why it matters:

Events are what make interaction possible on a website. Without them, a page would not respond to user input. Understanding events helps explain how buttons work, how forms are handled, and how dynamic behavior is created.

Real-world example:

When I click a button on a website, that click is an event. JavaScript detects that event and performs an action, like opening a menu, submitting a form, or updating part of the page.

My Note:

This helps me understand that interaction is not automatic. The page is actually waiting for something to happen, and then JavaScript responds to that event. It makes the idea of user interaction feel more structured instead of random.

Developer Thinking 🧠

Problem Solving

Meaning:

Problem solving in development is the process of breaking down a task or issue into smaller, manageable steps and figuring out how to achieve the desired outcome. Instead of thinking about code first, it involves understanding what needs to happen and then deciding how to approach it.

Why it matters:

Problem solving matters because writing code is only part of development. Most of the work involves figuring out what the problem actually is and how to solve it logically. Without this skill, it is easy to get stuck or rely too much on copying solutions without understanding them.

Real-world example:

If I want to build a to-do list, I would first think about what it needs to do: add items, remove items, and display them. Then I would break that down into steps before writing any code, instead of jumping straight into coding without a plan.

My Note:

This makes me realize that coding is not just about knowing syntax, but about thinking through problems step by step. It seems more important to understand what needs to happen before worrying about how to write the code for it.

Debugging

Meaning:

Debugging is the process of finding and fixing errors or unexpected behavior in code. It involves identifying what is not working, understanding why it is happening, and making changes to correct it.

Why it matters:

Debugging matters because code will not always work as expected, especially while learning. Being able to fix problems is a key part of development, and it is often more important than writing the code in the first place.

Real-world example:

If a button on a webpage is not working, debugging would involve checking if the event is connected correctly, if the code is running, and if there are any errors in the console. By testing different parts step by step, I can find where the issue is and fix it.

My Note:

I am starting to understand that errors are not just mistakes, but part of the process. Debugging seems like a skill that improves over time, and learning how to fix problems is just as important as learning how to build things.
