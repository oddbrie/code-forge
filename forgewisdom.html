Web Basics 🌐

What happens when you visit a website

Meaning:

By typing a url into your browser, you are requesting a server to return a series of files [like HTML, CSS, and JavaScript files], and the browser then reads those files and displays the website on your screen.

Why it matters:

This process involves a lot of communication between the browser and the server, and understanding this process is crucial for web development.

Real-world example:

When I visit Reddit, my browser sends a request to Reddit’s servers, which then return the HTML, CSS, and JavaScript files that make up the Reddit website. My browser then reads those files and displays the Reddit website on my screen; I am able to see the posts, comments, and interact with the site because of this process.

My Note:

I am not sure, other than my brief experience with MySpace in the early 2000s, if I ever really thought about how websites work before. I understood that there were servers and browsers, but I never really thought about the communication process between them. And I definitely never thought about how the browser reads the files and displays the website on the screen. It’s interesting to break it down and see how it all works together.

Browser vs Server

Meaning:

A browser is a software application that allows users to view websites [like Chrome or Safari], while a server stores everything. The browser asks the server to return a website, and the server sends back the data needed to display the requested website on the user's screen.

Why it matters:

It's important to know that my computer does not "hold" the website; instead it is stored on a server somewhere else. When I visit a website, my browser is essentially asking the server to send the website data to my computer. Communication. This explains why websites can be slow, unavailable, or behave differently depending on the server.

Real-world example:

When I open a website like Reddit, my browser (I use Chrome) sends a request to Reddit's servers. Reddit's servers then process that request and send back the necessary files [HTML, CSS, JavaScript] and my browser displays it so I can read posts, view comments, and interact with the site.

My Note:

I used to think that the browser and the website were basically the same thing. I now understand that the browser is the viewing software and the server is where the website data actually lives. This is a fundamental concept that I had not fully grasped before, and it helps me understand how the web works on a deeper level.

Request vs Response

Meaning:

A request is when a browser asks a server for something, like a website or data. A response is when the server sends back data or files to the browser. This back and forth communication is how the web works, from first request [loading] to each additional request [updating].

Why it matters:

The fundamental process of the web is based on this request-response cycle. And understanding this highlights how every action on a website works. Whether it's loading a page, submitting a form, or clicking a button, it all involves requests and responses between the browser and the server. This is the core of how the web functions.

Real-world example:

When I go to Reddit, my browser sends a request to Reddit's servers asking for the homepage. The server responds by sending back the necessary files and data, and my browser then builds and displays the Reddit homepage on my screen. If I click on a post, that action sends another request to the server and another response is returned.

My Note:

It's strange to stop and think about how often this happens, it's not just when I load a page... every click or action can trigger another request and response. This creates the dynamic loop of interaction on the web, and it's fascinating to understand how it all works together.
